# Наблюдения по эргономике

## Общие решения файловой волны

- `fs.readDirectory` возвращает отсортированные соседние имена и явные виды
  записей. Для глобального порядка путей дерево сортируется отдельно.
- Общий пакет `tree` использует явный стек, лимит общего числа записей и
  глубины, накапливает ошибки подкаталогов и не следует ссылкам. Версия
  зафиксирована в `PROVENANCE.json`; два потребителя сохраняют собственные тесты.
- В std/text пока нет публичного лексикографического comparator, а операторы
  `<`/`<=` для string отвергаются T0003. Разобрано как отсутствие API, не дефект
  сравнения чисел: сортировка в `tree` однократно кодирует каждый путь в Bytes,
  затем сравнивает готовые ключи без выделений на сравнении. Память O(суммы длин
  путей), время O(n log n) сравнений. Общий публичный sort/comparator требует
  отдельного обоснования; API языка не добавлялся только ради этой утилиты.
- Нельзя считать `fs.LimitExceeded` отказом лимита каталога: для него существует
  отдельный `fs.TooManyEntries`. Приёмка подтвердила исправленное сопоставление;
  глобальное переполнение теперь даёт отказ, сохраняя прежний выходной файл.
- Исходный defect `Ok(value)` от Result<void,E> исправлен в checker по D092:
  T0002 вместо внутреннего/тихого отказа, включая вложенные/именованные шаблоны.
  Для допустимого void-потребления остаётся `Ok(_)`.

## Оставшиеся общие ограничения

Escaping-mutable-capture warning и Result<T,never> transport остаются открытыми
в языке. Этот пакет их не реализует и не объявляет закрытыми. Полная CP42,
платформенная проверка, startup-бюджет и последующие CP41/CP39/CP40 также открыты.
Выводы по времени и памяти фиксируются после измерений в VERIFICATION.md.

Валидатор config v1/v2 повторно используется как отдельный пакет без переписывания
JSON-декодера. Дополнительное требование requiredFiles оставаться внутри корня
принадлежит проверяющему приложению, не меняет существующую схему config.
Неполный обход отражён явно: `unverified` предотвращает ложное утверждение,
что недоступный файл отсутствует. Все применимые замечания собираются до вывода.
